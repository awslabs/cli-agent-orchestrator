- **herdr: inbox messages are no longer typed into an open Claude Code dialog** (#896). herdr can report a pane as idle or done while an AskUserQuestion, permission or plan-approval dialog is open, and CAO then typed the queued message into the dialog, which took the trailing Enter as its answer. On the herdr backends CAO now reads the pane before typing an inbox message, assign or handoff into a terminal whose provider can recognise a dialog on screen (today Claude Code), and holds the message until the dialog is answered. This costs one pane read per delivery to such a terminal on herdr; other providers and tmux read nothing extra, and a failed pane read does not hold delivery. Two AskUserQuestion pages that Claude Code 2.1.330 draws for a call with several questions are now recognised as dialogs, on herdr and in tmux status detection: the question page whose footer reads `Enter to select · Tab/Arrow keys to navigate · Esc to cancel`, and the final "Review your answers" page, which has no footer. A hold is logged once when it starts (`Native-status pane check held input to <terminal>`) and once when it ends, with the retries in between at DEBUG.
